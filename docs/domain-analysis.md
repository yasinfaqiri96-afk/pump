# تحلیل دامنه — نرم‌افزار دیتابیس تانک تیل / پمپ استیشن (افغانستان)

سند تحلیل واقع‌گرایانه. مبنای طراحی دیتابیس و نرم‌افزار.

---

## ۰. تفکیک دو کسب‌وکار

اشتباه رایج: یکی گرفتن این دو. منطق انبار یکی، منطق فروش کاملاً فرق.

| | **Depot / تانک فارم (ذخیره‌گاه)** | **Pump Station (پمپ استیشن)** |
|---|---|---|
| فروش | عمده، با تانکر، بر اساس **تُن (MT)** یا لیتر @15°C | خرده، با نازل، بر اساس **لیتر مشاهده‌ای (ambient)** |
| مشتری | شرکت‌ها، پمپ‌ها، قراردادی | راننده، عام، نسیه‌دار |
| اندازه‌گیری | دیپ + دانسیته + حرارت + VCF | کنتور نازل (totalizer) |
| کسری | Transit loss + evaporation | Meter drift + سرقت + evaporation |
| پول | USD/AFN، حواله، اعتبار بلندمدت | نقد AFN، کوپن، نسیه کوتاه |

نرم‌افزار باید **هردو** را پشتیبانی کند چون بیشتر مالکان افغان هردو دارند (ذخیره‌گاه + چند پمپ).

## ۱. واقعیت‌های میدانی افغانستان — قیود طراحی

این‌ها تصمیم معماری را عوض می‌کنند، نه صرف «خوب است داشته باشیم»:

1. **برق قطع** — نرم‌افزار باید offline کار کند. Cloud-only = مرگ پروژه.
2. **انترنت ضعیف/گران** — سرور محلی در استیشن، sync دوره‌ای به مرکز.
3. **کمپیوتر ضعیف** — Windows 10 قدیمی، 4GB RAM. Electron سنگین + DB سنگین = کند.
4. **ATG ندارند** — ۹۵٪ استیشن‌ها دیپ دستی با متر و خمیر آب. پس **دیپ دستی باید شهروند درجه‌یک سیستم باشد**، نه fallback.
5. **کنتور نازل مکانیکی** — rollover در ۶ یا ۸ رقم (999999 به 000000). منطق rollover لازم.
6. **سواد کمپیوتری پایین اپراتور** — UI ساده، کیبورد-محور، عددی، حداقل فیلد.
7. **سرقت مسئله شماره ۱** — audit trail کامل، حذف ممنوع، تفکیک وظیفه (اپراتور دیپ نزند، دیپ‌زن فروش ثبت نکند).
8. **چند ارزی** — خرید USD، فروش AFN، بعضاً PKR/IRR. نرخ روزانه. FX gain/loss واقعی است.
9. **حواله (Hawala)** — بانک کم استفاده. حواله باید نوع پرداخت رسمی در سیستم باشد با صراف، کمیشن، شماره حواله.
10. **تقویم هجری شمسی** — گزارش، بستن ماه، سال مالی همه شمسی. میلادی فقط داخلی.
11. **RTL دری/پشتو** — از روز اول، نه بعداً.
12. **قیمت دولتی سقف‌دار** — تغییر قیمت مکرر (گاهی هفته‌ای). تاریخچه قیمت اجباری.
13. **مالیات** — BRT، مالیه معاملات، مالیه موضوعی کرایه، مالیه معاش. سیستم یک دفتر درست بدهد و گزارش مالیاتی به شکل view جدا.
14. **گاز مایع (LPG)** — بسیار پررواج. واحد **کیلوگرام**، نه لیتر. تانک تحت فشار، سیلندر، اتوگاز. منطق کاملاً جدا.
15. **کیفیت سوخت / اختلاط** — دیزل با تیل خاک مخلوط می‌شود (تقلب یا سردسازی زمستان). سیستم باید ثبت آزمایش دانسیته داشته باشد.

## ۲. ماژول‌ها

### الف) داده‌های پایه
- شرکت / شعبه / استیشن (multi-site از روز اول)
- محصول: پطرول، دیزل، تیل خاک، LPG، موبلایل، فلترها، دکان
- واحد: لیتر، لیتر@15، MT، کیلوگرام، عدد، کارتن — با ضریب تبدیل
- تانک: ظرفیت، محصول، نوع (زمینی/زیرزمینی)، dead stock
- **جدول کالیبراسیون تانک (Strapping / Dip Chart)** — mm به لیتر. جدول جداگانه، هزار سطر، درون‌یابی خطی
- دستگاه (Dispenser) به نازل (Nozzle) به تانک. رابطه چند-به-یک
- کارمند، شفت، نقش، صلاحیت

### ب) خرید و ورود (Receiving)

سناریو واقعی، به ترتیب:

1. قرارداد با تهیه‌کننده (وارد کننده / گمرک حیرتان / تورغندی)
2. سفارش خرید (PO): مقدار MT، قیمت، ارز، شرط تحویل
3. بارنامه (Waybill): تانکر، شماره پلیت، راننده، شماره مهر (Seal)
4. ثبت مقدار مبدا: MT + لیتر@15 + دانسیته مبدا + حرارت مبدا
5. رسیدن تانکر به استیشن — کنترل مهر
6. دیپ قبل تخلیه (mm به لیتر) + دیپ آب قبل
7. تخلیه
8. صبر ۳۰ دقیقه، سپس دیپ بعد تخلیه + دیپ آب بعد
9. گرفتن نمونه: دانسیته + حرارت
10. محاسبه دریافتی، تبدیل به @15 و MT
11. محاسبه کسری ترانزیت و ادعا بر ترانسپورتر اگر بیش از تولرانس

```
دریافتی = (لیتر_بعد − آب_بعد) − (لیتر_قبل − آب_قبل)
کسری ترانزیت = مقدار_مبدا − دریافتی
```

تولرانس قابل تنظیم per محصول (مثلاً 0.3٪ دیزل، 0.5٪ پطرول).

### ج) موجودی و انبار
- موجودی دفتری (Book stock) per تانک، لحظه‌ای
- موجودی فزیکی (Physical) از دیپ
- انتقال بین تانک، بین استیشن، بین شعبه
- تعدیل (Adjustment) با دلیل اجباری + تاییدکننده
- **قفل دوره** — بعد بستن ماه، ثبت گذشته ممنوع مگر با سند معکوس

### د) دیپ و مغایرت (قلب سیستم)

```
Book  = افتتاحیه + ورودی − فروش − انتقال_خروجی + انتقال_ورودی ± تعدیل
Var   = Physical − Book
Var%  = Var / (افتتاحیه + ورودی) × 100
```

- دیپ روزانه اجباری (اول و آخر شفت)
- حرارت + دانسیته در هر دیپ
- تحلیل روند: مغایرت تصادفی = خطای اندازه‌گیری. مغایرت یک‌طرفه مداوم = **نشتی تانک یا سرقت**
- گزارش تجمعی مغایرت ۳۰ روزه per تانک — این گزارش سرقت را لو می‌دهد

### ه) شفت و فروش خرده

باز کردن شفت:
- اپراتور، تاریخ/ساعت، صندوق افتتاحیه (float)
- قرائت افتتاحیه هر نازل (electronic + mechanical هردو)
- دیپ افتتاحیه هر تانک

بستن شفت:
- قرائت اختتامیه هر نازل
- محاسبه فروش نازل
- منهای تست/کالیبراسیون برگشتی به تانک
- ضرب در ضریب کالیبراسیون نازل (meter factor)
- مبلغ = لیتر × قیمت فعال
- تفکیک قبض: نقد / نسیه / کوپن / کارت / انتقالی
- شمارش نقد صندوق و محاسبه کسر یا اضافه
- دیپ اختتامیه و محاسبه مغایرت تانک

کسری صندوق به بدهی اپراتور تبدیل شود و از معاش کسر گردد (ماژول HR).

**تصمیم لازم:** تغییر قیمت وسط شفت. یا فروش به دو بازه قیمتی شکسته شود، یا سیاست این باشد که تغییر قیمت فقط با بستن اجباری شفت ممکن است. پیشنهاد: دومی، ساده‌تر و ضدتقلب‌تر.

### و) فروش عمده (تانکر خروجی)
- سفارش فروش، بارگیری، دیپ قبل/بعد، بارنامه، مهر، فاکتور
- قیمت‌گذاری بر MT یا لیتر@15
- تحویل به مشتری با دیپ مقصد — کسری راه بر عهده که؟ شرط قرارداد در سیستم ثبت شود

### ز) مشتریان و حسابات دریافتنی
- سقف اعتبار، مدت اعتبار
- دفتر معین مشتری، صورتحساب
- Aging: 0-30، 31-60، 61-90، +90
- تسویه جزیی، تخصیص پرداخت به فاکتور
- **بلاک خودکار** وقتی از سقف گذشت — با صلاحیت override و لاگ

### ح) تهیه‌کنندگان و پرداختنی
مشابه بالا، معکوس. به‌علاوه پیش‌پرداخت (بسیار رایج: پول قبل، تیل بعد).

### ط) قیمت‌گذاری و بهای تمام‌شده
- جدول قیمت فروش با `effective_from` — هرگز update، همیشه سطر جدید
- روش بهای تمام‌شده: **Weighted Average per تانک** (توصیه) یا FIFO
- WAC بعد هر ورودی دوباره محاسبه:

```
WAC_new = (Qty_old × WAC_old + Qty_in × Cost_in) / (Qty_old + Qty_in)
```

- هزینه‌های جانبی وارد بهای تمام‌شده شوند: کرایه، گمرک، تخلیه، کسری — **landed cost**
- سود ناخالص = فروش − (لیتر فروخته × WAC)

### ی) خزانه و بانک
- صندوق per استیشن per شفت
- بانک، حواله، صرافی
- چند ارزی: هر تراکنش ارز اصلی + نرخ + معادل ارز پایه
- جدول نرخ ارز روزانه
- تجدید ارزیابی آخر ماه، ثبت FX gain/loss

### ک) مصارف
معاش، کرایه، برق، جنراتور (مصرف تیل خودی — باید از موجودی کم شود، وگرنه مغایرت کاذب می‌سازد)، ترمیم، مالیه.

### ل) حسابداری دوطرفه
هر عملیات سند بزند. بدون این، نرم‌افزار فقط «دفترچه» است نه سیستم.

```
ورود تیل:      بد: موجودی تانک        بس: حسابات پرداختنی
فروش نقد:      بد: صندوق              بس: فروش + مالیه
               بد: بهای تمام‌شده       بس: موجودی تانک
فروش نسیه:     بد: مشتری              بس: فروش
کسری تانک:     بد: کسری و ضایعات      بس: موجودی تانک
کسری صندوق:    بد: مطالبات کارمند     بس: صندوق
```

خروجی: تراز آزمایشی، سود و زیان، بیلانس، دفتر معین.

### م) گزارشات (چیزی که مالک واقعاً می‌خواهد)
1. گزارش روزانه استیشن — یک صفحه: فروش، نقد، نسیه، دیپ، مغایرت
2. مغایرت تانک — روزانه / ماهانه / تجمعی
3. کارکرد اپراتور — فروش، کسری صندوق، روند
4. سود ناخالص per محصول per استیشن
5. Aging مشتریان
6. گردش موجودی و روزهای پوشش (days of cover)، هشدار سفارش مجدد
7. مقایسه استیشن‌ها
8. کسری ترانزیت per ترانسپورتر — ترانسپورتر خیانت‌کار را لو می‌دهد

### ن) امنیت و ممیزی
- نقش: مالک، مدیر، محاسب، مدیر استیشن، اپراتور، دیپ‌زن
- Audit log تغییرناپذیر: چه کسی، چه وقت، مقدار قدیم، مقدار جدید، IP
- **حذف نرم هم برای اسناد مالی قبول نیست** — فقط سند معکوس
- ورود دو-عاملی برای مالک، PIN برای اپراتور

## ۳. فرمول‌های اصلی

بدون این‌ها نرم‌افزار عددش غلط است.

### تبدیل حجم به ۱۵ درجه (ASTM D1250 / API MPMS ch.11.1)

**توجه به واحد — این مهم‌ترین نکته این بخش است:**
فرمول α با دانسیته به **kg/m³** کار می‌کند (مثلاً 840)،
ولی تبدیل به تُن با دانسیته به **kg/لیتر** (مثلاً 0.84).
اگر این دو قاطی شوند، نتیجه ۱۰۰۰ برابر غلط می‌شود.

در کد، دانسیته همیشه به **kg/لیتر** ذخیره و رد و بدل می‌شود؛
`Petro.normDensity()` هر ورودی را (چه 0.84 چه 840) به kg/لیتر تبدیل می‌کند،
و فقط داخل `vcf()` برای فرمول α در ۱۰۰۰ ضرب می‌گردد.

```
ρ15     = دانسیته در 15°C به kg/لیتر   (مثلاً 0.84)
ρ15_m3  = ρ15 × 1000                   (kg/m³ — فقط برای α)
T       = حرارت مشاهده‌ای  (°C)
α       = K0/ρ15_m3² + K1/ρ15_m3       (ضریب انبساط حجمی، 1/°C)
ΔT      = T − 15
VCF     = exp(−α·ΔT·(1 + 0.8·α·ΔT))
V15     = V_obs × VCF
MT      = V15 × (ρ15 − 0.0011) / 1000  ← 0.0011 kg/L تصحیح وزن در هوا
```

نمونه کنترل‌شده (در `test/petroleum.test.js` قفل شده است):
دیزل، ρ15 = 0.84، T = 30°C
α = 186.9696/840² + 0.4862/840 = 0.00084379
VCF = exp(−0.00084379 × 15 × (1 + 0.8 × 0.00084379 × 15)) = **0.9872964**
۱۰,۰۰۰ لیتر @15° × (0.84 − 0.0011) / 1000 = **8.389 MT**

ضرایب K0/K1 per گروه محصول:

| گروه | K0 | K1 |
|---|---|---|
| Crude | 613.9723 | 0 |
| پطرول / بنزین | 346.4228 | 0.4388 |
| تیل خاک / جت | 594.5418 | 0 |
| دیزل / فیول اویل | 186.9696 | 0.4862 |

اگر فقط دانسیته مشاهده‌ای داری و ρ15 نداری، حل تکراری (iteration) لازم است تا همگرا شود.

### دیپ به حجم

```
حجم_کل  = درون‌یابی خطی در جدول کالیبراسیون تانک
حجم_آب  = درون‌یابی با دیپ آب
حجم خالص = حجم_کل − حجم_آب
```

تانک افقی کج (tilt) نیاز به تصحیح شیب دارد.

### فروش نازل

```
raw = closing − opening
if raw < 0:  raw = closing + 10^meter_digits − opening    # rollover
sold_l = (raw − test_return_l) × meter_factor
```

### مغایرت

```
Book_close = Book_open + Receipts − Sales − TransferOut + TransferIn + Adjust
Variance   = Physical_close − Book_close
Var%       = Variance / (Book_open + Receipts) × 100
Flag اگر |Var%| > tolerance_pct
```

### LPG (کیلوگرام)

```
جرم = حجم_مایع × دانسیته_مایع(T)
تانک تحت فشار: پرشدگی حداکثر ۸۵٪ حجم آبی
سیلندر: وزن پر − وزن خالی (tare) = محتوا
```

## ۵. تکنولوژی — توصیه

| تاریخ شمسی | `dayjs-jalali` در JS، `PersianCalendar` در .NET | |

### چرا Postgres، نه SQL Server، نه SQLite
- SQL Server Express: سقف ۱۰GB. برای چند استیشن و چند سال داده کم می‌آید.
- SQLite: برای تک-کاربر خوب. با چند کاربر همزمان (اپراتور + محاسب + مدیر) قفل می‌شود. رد.
- Postgres: نقطه متعادل.

### معماری Sync

```
هر استیشن: Postgres محلی + اپ محلی  →  کار کامل آفلاین
تغییرات در جدول outbox  (append-only, UUIDv7)
Sync worker: هر X دقیقه اگر انترنت بود  →  push به مرکز
مرکز (VPS): Postgres تجمیعی، فقط خواندن، داشبورد مالک
ID ها UUIDv7  →  بدون تضاد، مرتب زمانی
مرکز هرگز داده عملیاتی به استیشن push نکند، جز: قیمت، مشتری، کاربر
```

### فازبندی
- **فاز ۱ (۲-۳ ماه)** — پایه + دیپ + شفت + فروش نقد/نسیه + مغایرت + گزارش روزانه
- **فاز ۲** — خرید/ورود + WAC + مشتری/تهیه‌کننده + خزانه
- **فاز ۳** — حسابداری دوطرفه + مالیه + چند استیشن + sync
- **فاز ۴** — LPG + موبلایل/دکان + ATG integration + اپ موبایل مالک

## ۶. ریسک‌ها و تله‌ها

1. **تغییر قیمت وسط شفت** — سیاست را اول تعیین کن.
2. **گرد کردن** — لیتر ۳ رقم اعشار، پول ۲ رقم. جمع سطرها با جمع کل نمی‌خواند اگر بی‌دقت باشی.
3. **تانک مشترک بین چند نازل** — مغایرت را نمی‌شود به یک نازل نسبت داد. طراحی per-tank باشد نه per-nozzle.
4. **دیپ در تانک نیمه‌پر بعد تخلیه** — سطح مواج، عدد غلط. قاعده: ۳۰ دقیقه صبر.
5. **ورود غلط عدد دیپ** — validation: اختلاف با دیپ قبلی بیش از X٪، هشدار + تایید مدیر.
6. **شفت باز مانده** — گزارش را خراب می‌کند. job خودکار هشدار بدهد.
7. **نسیه بدون سند** — حداقل شماره تماس و شماره ثبت اجباری.
8. **دفتر دوگانه** — یک منبع حقیقت بساز، گزارش مالیاتی را به شکل view جدا کن. دو دیتابیس نساز.
9. **دور زدن سیستم (فروش دستی)** — مقایسه فروش کنتور با فروش ثبت‌شده. اختلاف یعنی فروش خارج سیستم.

## ۷. سوالات باز — قبل کدنویسی جواب لازم

1. تک استیشن یا زنجیره؟ فعلاً چند تا؟
2. LPG داری؟ (منطق جدا، حدود ۳۰٪ کار اضافه)
3. ذخیره‌گاه عمده هم داری یا فقط پمپ خرده‌فروشی؟
4. حسابداری دوطرفه کامل، یا فقط عملیات + سود و زیان ساده؟
5. ارز پایه دفاتر: AFN یا USD؟
6. Stack نرم‌افزار قبلی (وارد کنندگان) چه بود؟ اگر منطقی است همان را نگه دار.
7. تعداد کاربر همزمان؟ اپراتور مستقیم وارد می‌کند یا محاسب از روی کاغذ؟
