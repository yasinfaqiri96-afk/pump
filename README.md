# سیستم مدیریت تانک تیل و پمپ استیشن

نرم‌افزار دیتابیس برای پمپ استیشن‌ها و ذخیره‌گاه‌های تیل در افغانستان.
کار آفلاین · تقویم هجری شمسی · دری · تحلیل ضد-تقلب.

---

## تازه چه اضافه شده

| چه چیز | کجاست |
|---|---|
| **انتقال تیل بین تانک‌ها** | تانک‌ها ← تانک ← انتقال تیل |
| **فروش قرضی به موترهای مشتری قراردادی** | مشتری ← موترها · شفت ← فروش قرضی |
| **تغییر نرخ وسط شفت** | نرخ‌نامه ← ثبت نرخ ← «در شفت جاری» |
| **بستن روز** | راپورها ← راپور روزانه ← بستن روز |
| **بکاپ داخل نرم‌افزار + برگرداندن** | تنظیمات ← بکاپ |
| **تاریخچه جدول سنجش و کالیبراسیون نازل** | تانک ← جدول سنجش · تنظیمات ← نازل |
| **کار با دالر و کلدار** | همه فورم‌های پولی |
| **راپورهای جدید** | فروش قرضی · فروش بر اساس موتر · انتقال‌ها · کالیبراسیون |

دو چیز که کار روزانه را راحت‌تر می‌کند:

- **فورم‌ها ساده‌تر شدند.** ورود تیل حالا ۴ پله کوتاه است، نه یک صفحه دراز.
  هر خانه‌ای که همیشه لازم نیست، زیر «جزئیات بیشتر» رفته.
- **دو بار زدن دکمه دیگر سند را دو بار ثبت نمی‌کند.** اگر انترنت یا شبکه
  یک لحظه قطع شود و دوباره بزنید، سیستم می‌فهمد و سند دوم نمی‌سازد.

جزئیات فنی: [docs/v2-upgrade.md](docs/v2-upgrade.md)

## راه‌اندازی

### ضرورت
- **Node.js نسخه ۲۲ یا بالاتر** — تنها چیزی که نصب می‌شود. از [nodejs.org](https://nodejs.org) بگیرید.
- هیچ وابستگی دیگری نیست. `npm install` ضرورت ندارد. انترنت ضرورت ندارد.

### شروع
روی **`start.bat`** دوکلیک کنید. تمام.

مرورگر خودکار باز می‌شود روی `http://localhost:8080`.

```
کاربر پیش‌فرض:  admin
پین:            1234
```

**بعد از اولین ورود، پین را عوض کنید** — تنظیمات ← کاربران.

### استفاده از چند کمپیوتر (شبکه استیشن)
سرور را فقط روی **یک** کمپیوتر اجرا کنید. آدرس شبکه در پنجره سیاه نشان داده می‌شود:

```
شبکه :  http://192.168.1.15:8080
```

کمپیوترهای دیگر همان آدرس را در مرورگر باز کنند. موبایل و تابلت هم کار می‌کند.

### تغییر پورت
```
set PORT=9000 && start.bat
```

## بکاپ

**آسان‌ترین راه:** داخل خود نرم‌افزار — **تنظیمات ← بکاپ**.

آنجا می‌بینید:

- آخرین بکاپ کی گرفته شده
- محل ذخیره بکاپ‌ها
- دکمه **«گرفتن بکاپ حالا»**
- فهرست بکاپ‌های موجود

**بکاپ خودکار:** سیستم خودش هر روز یک بکاپ می‌گیرد. اگر بکاپ کهنه شود،
در صفحه هشدارها به شما می‌گوید.

**ذخیره روی USB یا درایو دیگر:** در تنظیمات ← بکاپ، در خانه «پوشه بکاپ»
مسیر را بنویسید — مثلاً `D:\pump-backup`. بکاپ‌های بعدی همان‌جا ذخیره می‌شوند.

**قاعده طلایی:** بکاپ روی همان کمپیوتر، بکاپ نیست. اگر هارد خراب شود
هر دو با هم می‌روند. **هر شب یک کاپی روی USB بگیرید و آن را جای دیگر بگذارید.**

**برگرداندن بکاپ:** تنظیمات ← بکاپ ← در فهرست، کنار فایل دکمه «برگرداندن».
سیستم اول فایل را کنترول می‌کند که سالم باشد، بعد از وضعیت فعلی یک بکاپ
اضطراری می‌گیرد، و بعد برمی‌گرداند. برای تایید باید کلمه «برگردان» را
بنویسید. بعد از آن همه باید دوباره وارد سیستم شوند.

> **هشدار:** برگرداندن بکاپ یعنی هر معامله‌ای که بعد از آن بکاپ ثبت شده
> از بین می‌رود. فقط وقتی این کار را بکنید که واقعاً لازم باشد.

`backup.bat` هم هنوز کار می‌کند — برای وقتی که نرم‌افزار باز نیست.
تمام دیتابیس یک فایل است: `data\pump.db`

## راهنمای سریع کار روزانه

### ۱ — تنظیم اولیه (یک بار)
1. **تنظیمات ← استیشن‌ها** — استیشن خود را ثبت کنید
2. **تنظیمات ← محصولات** — پطرول، دیزل و غیره (پیش‌فرض ساخته شده)
3. **تنظیمات ← تانک‌ها** — هر تانک با ظرفیت و موجودی افتتاحیه
4. **جدول سنجش هر تانک را بارگذاری کنید** ← بدون این دیپ کار نمی‌کند
5. **تنظیمات ← دستگاه و نازل** — هر نازل به کدام تانک وصل است
6. **نرخ‌نامه** — نرخ هر محصول
7. **مشتریان ← کارمندان** — اپراتوران را ثبت کنید

### ۲ — کار هر روز

ترتیب کار از صبح تا شب:

```
باز کردن شفت  →  ریدینگ شروع  →  فروش روزانه
      ↓
فروش قرضی (اگر بود)  →  ورود تانکر (اگر بود)  →  دیپ کنترولی
      ↓
مصارف  →  ریدینگ ختم  →  تسویه شفت  →  راپور روزانه  →  بستن روز
```

| کار | کجا |
|---|---|
| باز کردن شفت + ریدینگ ابتدایی نازل | شفت ← باز کردن شفت |
| ثبت دیپ افتتاحیه | دیپ ← ثبت دیپ (نوع: افتتاحیه شفت) |
| **فروش قرضی به موتر مشتری قراردادی** | شفت ← فروش قرضی |
| تخلیه تانکر | ورود تیل ← ثبت تخلیه جدید |
| **انتقال تیل از یک تانک به تانک دیگر** | تانک‌ها ← تانک ← انتقال تیل |
| فروش تانکر خروجی | فروش عمده |
| ثبت مصارف | مصارف |
| **تغییر نرخ وسط شفت** | نرخ‌نامه ← ثبت نرخ ← «در شفت جاری» |
| بستن شفت + شمارش صندوق | شفت ← بستن شفت |
| دیپ اختتامیه | داخل فورم بستن شفت یا جداگانه |
| کنترل روز | راپورها ← راپور روزانه |
| **بستن روز** | راپورها ← راپور روزانه ← بستن روز |

### ۳ — کنترل هفتگی مالک
1. **هشدارها** — هر هشدار بلند را بررسی کنید
2. **راپورها ← کسری تانک** — تانکی که «کسری یک‌طرفه مداوم» دارد یعنی نشتی یا دزدی
3. **راپورها ← کارکرد اپراتور** — کدام اپراتور مکرر کسری صندوق دارد
4. **راپورها ← فروش بر اساس موتر** — اگر مصرف یک موتر ناگهان زیاد شد، کنترل کنید
5. **راپورها ← کسری راه ترانسپورتران** — کدام ترانسپورتر کم می‌آورد
6. **راپورها ← سن طلبات** — کدام مشتری بالای ۹۰ روز بدهکار است
7. **راپورها ← کالیبراسیون و مهر** — کدام نازل یا تانک به کنترول ضرورت دارد
8. **تنظیمات ← بکاپ** — مطمئن شوید بکاپ تازه است و یک کاپی روی USB دارید

## جدول سنجش تانک — مهم‌ترین قدم

بدون جدول سنجش، دیپ به لیتر تبدیل نمی‌شود.

**بهترین راه:** جدول واقعی سنجش تانک را از شرکت سازنده یا اداره معیارات بگیرید و در
بخش «جدول سنجش» بچسپانید. هر سطر:

```
0     0
10    285
20    572
30    861
```

ستون اول = میلی‌متر دیپ · ستون دوم = لیتر

**راه دوم (تخمینی):** «تولید خطی» — فقط برای تانک استوانه‌ای **عمودی** درست است.
برای تانک افقی خطای بزرگ می‌دهد.

## هشدارهای ضد-تقلب

سیستم خودکار این علامت‌ها را بلند می‌کند:

| کد | یعنی چه |
|---|---|
| `DIP_VARIANCE` | کسری تانک بالای تولرانس |
| `DIP_REPEATED` | عدد دیپ عیناً برابر دیپ قبلی — دیپ‌زن اندازه نگرفته |
| `DIP_JUMP` | پرش بزرگ سطح بدون ثبت تخلیه |
| `TRANSIT_LOSS` | کسری ترانزیت بالای تولرانس |
| `SEAL_MISMATCH` | شماره مهر مبدا و مقصد نمی‌خواند — تانکر باز شده |
| `DENSITY_MISMATCH` | دانسیته مقصد با مبدا فرق زیاد دارد — تعویض محموله |
| `QUALITY_FAIL` | محموله با کیفیت نامناسب ثبت شده |
| `TANK_OVERFLOW` | سطح تانک از ظرفیت گذشته |
| `NEGATIVE_STOCK` | فروش شفت بیش از موجودی — دیپ غلط یا فروش خارج سیستم |
| `CASH_SHORT` | کسری صندوق در شفت |
| `CASH_OVER` | اضافه غیرعادی صندوق — فروش ثبت‌نشده یا پوشاندن کسری قبلی |
| `CREDIT_OVERRIDE` | مدیر سقف اعتبار مشتری را دور زده |
| `ADJUST_FREQUENT` | یک کاربر مکرر موجودی را اصلاح کرده |
| `PRICE_MID_SHIFT` | نرخ عوض شده در حالی که شفت باز بوده |
| `BACKDATE_AFTER_CLOSE` | سندی با تاریخ روزی که بسته شده ثبت شده |
| `DAY_REOPENED` | روز بسته‌شده دوباره باز شده |
| `CREDIT_TICKET_EXCESS` | بلیت قرضی بیشتر از فروش کنتور آن محصول |
| `CALIBRATION_EXPIRED` | کالیبراسیون نازل یا جدول سنجش تانک نزدیک ختم است |
| `BACKUP_OVERDUE` | مدت زیادی است بکاپ گرفته نشده |
| `DOC_REVERSED` | یک سند مهم برگشت خورده |
| `SEAL_REMOVED` | مهر یک تجهیز باز شده |

هشدار بسته‌شده پاک نمی‌شود — دلیل بستن و نام کسی که بست ثبت می‌ماند.

## نقش‌ها و صلاحیت

| نقش | چه کاری کرده می‌تواند |
|---|---|
| **مالک** | همه چیز + کاربران + ثبت وقایع |

## معماری فنی

### سه دفتر تغییرناپذیر
```
stock_move  — هر لیتر که وارد یا خارج شد، یک سطر. فقط افزودنی.
money_move  — هر افغانی که حرکت کرد، یک سطر. فقط افزودنی.
audit_log   — هر تغییر، با نام کاربر و وقت.
```

موجودی تانک هرگز به‌عنوان یک عدد ذخیره نمی‌شود — همیشه از `stock_move` جمع می‌شود.
یعنی **موجودی هرگز خراب نمی‌شود** و هر عدد تا سند اصلی قابل ردیابی است.

هیچ سند مالی حذف نمی‌شود. اصلاح فقط با سند معکوس.

### محاسبات نفتی — ASTM D1250 / API MPMS 11.1
```
α    = K0/ρ15² + K1/ρ15              (ρ به kg/m³ — مثلاً 840)
VCF  = exp(−α·ΔT·(1 + 0.8·α·ΔT))
V15  = V_obs × VCF
MT   = V15 × (ρ15 − 0.0011) / 1000   (ρ به kg/لیتر — مثلاً 0.84)
```

**دو واحد مختلف در دو فرمول.** برای همین ثقلت همیشه به kg/لیتر ذخیره
می‌شود و `Petro.normDensity()` هر ورودی را (چه `0.84` چه `840`) به همان
واحد تبدیل می‌کند. کاربر می‌تواند هر کدام را بنویسد.

**کاربر عادی هیچ‌کدام از این‌ها را نمی‌بیند.** او فقط می‌بیند:
«حجم ثبت‌شده: ۱۵٬۰۰۰ لیتر · حجم اصلاح‌شده: ۱۴٬۷۸۴ لیتر» و این جمله:
«اصلاح بر اساس حرارت و ثقلت خودکار انجام شد.»

فروش نازل با در نظر گرفتن چرخش کنتور:
```
raw = closing − opening
اگر raw < 0:  raw += 10^ارقام_کنتور
فروش = (raw − برگشت_تست) × ضریب_کنتور
```

### تکنولوژی
| لایه | چه چیز |
|---|---|
| دیتابیس | SQLite داخلی Node (`node:sqlite`) — بدون نصب جدا |
| سرور | Node.js خالص (`node:http`) — بدون فریم‌ورک |
| رابط | HTML/CSS/JS خالص — بدون build، بدون کتابخانه |
| وابستگی | **صفر** |

انتخاب عمدی: هیچ `npm install` لازم نیست، پس نصب در جایی که انترنت نیست کار می‌کند
و ده سال بعد هم بدون شکستن وابستگی اجرا می‌شود.

## سوالات معمول

**دیتابیس کجاست؟** `data\pump.db` — یک فایل. همین را بکاپ بگیرید.

**اگر برق برود؟** داده از دست نمی‌رود (WAL mode). سرور را دوباره اجرا کنید.

**انترنت لازم است؟** نخیر. هیچ‌وقت.
